OAuth Scope & Data Handling Walkthrough

Prepared for Google's OAuth app verification review (sensitive + restricted scope justification, CASA security assessment). Documents exactly what is requested, why, and how the data is handled end to end.

App: Daily-flow (daily-flow-503302) · app.daily-flow.io Contact: Rusty Chapin, rusty.chapin@gmail.com
What Daily-flow Is

A daily commitment list, built from a user's own inbox and calendar.

Daily-flow is a single-user productivity app. A user connects their Google account (read-only), and Daily-flow reads their Gmail and Calendar to surface the commitments and deadlines actually contained in that content — not a broadcast tool, not a multi-tenant workplace app, no data shared between users.

  • One connected Google account per user; read-only access only.
  • Output is private to that user: a personal "Today" list of commitments and deadlines.
  • No advertising, no data resale, no cross-user data sharing of any kind.
Scopes Requested

Three scopes. Each mapped to one specific, visible feature.

ScopeTypeWhy it's needed
gmail.readonly Restricted Read email content to detect real commitments and deadlines (e.g. "reply by Friday," a school permission-slip due date) that never appear on a calendar. Read-only — Daily-flow never sends, deletes, or modifies email.
calendar.readonly Restricted Read calendar events so they can be merged chronologically with email-derived commitments into one "Today" list, and so conflicts between a meeting and a personal commitment can be surfaced. Read-only — Daily-flow never creates or edits events.
userinfo.email Non-sensitive Identify which Google account was connected, so it can be shown back to the user in Settings and disconnected individually.

No write scopes of any kind are requested for Gmail or Calendar.

End-to-End Data Flow

What happens to a message from fetch to display.

1. Fetch from Gmail/Calendar API (OAuth, read-only)
→
2. In-memory candidate extraction, capped at 50,000 chars
→
3. One classification call to Anthropic (sender + subject + capped body)
→
4. Only the model's short output stored (deadline text, tags)
→
5. Shown to the user in their own "Today" list

The raw email/calendar body is never written to a database and never appears in a log line at any point in this pipeline — proven by an automated test suite, not just a code-review claim (see "Testing the Guarantee").

Data Minimization

The smallest slice of content that can do the job.

What's sent to the AI classifier

Sender, subject line, and up to 16,000 characters of plain-text body (HTML converted to plain text first) — one call per message, in memory only, never logged or persisted.

What's actually stored

Only the model's own short generated output: whether it's a commitment, the extracted deadline, a short source snippet, and goal tags — never the full original message.

What's never stored

The full email body, the full calendar event description, and any raw content beyond the short snippet needed to show the user why an item was surfaced.

Third parties

Anthropic (the classification model) is the only third party that ever processes message content, and only per the minimization above — confirmed against Anthropic's current no-training, 30-day-default-deletion commercial terms.

Data Retention

Extracted content expires. It does not accumulate forever.

  • 35-day TTL on every extraction/goal-tag/watermark record, set automatically at write time — enforced natively by Firestore's built-in TTL feature, the same mechanism already used for session tokens and rate-limit records.
  • 7-day TTL, plus immediate content scrub when a user dismisses an item: the source snippet and deadline text are blanked in the same request that records the dismissal — not a later batch job.
  • Structural metadata only (whether it was a commitment, a confidence score, timestamps) is kept slightly longer, for the user's own accuracy reporting — never the underlying quoted content.
  • Full account/data deletion is supported on disconnect — a disconnect revokes the OAuth token at Google directly, not just a local database flag.
Security Controls

Credentials and tokens are never handled casually.

Token encryption

OAuth refresh tokens are encrypted at rest using Google Cloud KMS in production — not stored in plaintext, not encrypted with an application-level static key.

Secret management

Every credential (OAuth client secret, API keys, signing secrets) lives in Google Secret Manager. Nothing is hardcoded or committed to source control.

Real revocation

Disconnecting a Google account calls Google's own token-revocation endpoint — the grant is actually torn down, not just hidden in the UI.

Least privilege

Only read scopes are requested. No Gmail send/modify/delete scope, no Calendar write scope, ever.

Transport security

All traffic (browser ↔ app, app ↔ Google API, app ↔ Anthropic API) is HTTPS/TLS only.

Infrastructure

Runs on Google Cloud Run with a dedicated least-privilege service account — no shared credentials across services.

Testing the Guarantee

"Never persisted or logged" is a passing test, not a promise.

A dedicated regression test suite runs a real message with a long, uniquely identifiable marker string through the entire fetch → classify → store pipeline, then inspects every database write and every log line produced — for each connector — and asserts the marker never appears in either. The test is designed to actually fail if a future change accidentally logged or stored raw content, not just to assert "nothing happened."

  • Runs against a real Firestore emulator and a captured log buffer — not a mock that assumes the answer.
  • Included in the CI pipeline that gates every deploy — this guarantee cannot silently regress.
User-Facing Transparency

What the user sees and controls.

Consent screen

Google's standard OAuth consent screen, listing exactly the three scopes above — nothing requested is undisclosed.

Settings page

Shows which Google account is connected and offers one-click disconnect at any time, with no retention beyond that action.

Privacy Policy

Live at daily-flow.io/privacy — includes the Limited Use disclosure required for restricted-scope Google API data, naming exactly what's accessed and why.

Dismiss = delete

Dismissing a surfaced item immediately scrubs its underlying content, not just hides it from view.
